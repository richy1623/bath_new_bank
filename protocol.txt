This document details the protocol for interacting with the NewBank server.  

REGISTER
Type REGISTER on its own at the "Enter Username" prompt, before logging in.
The server then asks for each detail on its own line:
  Enter Full Name      e.g. Alice Smith      (can contain spaces)
  Enter Username       e.g. asmith           (no spaces)
  Enter Password       e.g. my secret        (can contain spaces)
Adds a new customer with no accounts (so nothing to show and a 0.00 total),
and gives them a unique number ID (one more than the highest ID so far).
Returns SUCCESS, or FAIL: <reason>, one of:
  FAIL: Full name cannot be empty
  FAIL: Username cannot be empty or contain spaces
  FAIL: Password cannot be empty
  FAIL: Full name, username and password cannot contain file separators (, ; # | ~ :)
  FAIL: Username <username> is already taken
  FAIL: Your details could not be saved, please try again later
  FAIL: Customer data could not be loaded, so new customers cannot be saved right now
Typing the old one-line form (REGISTER followed by details) returns:
  FAIL: Type REGISTER on its own and you will be asked for each detail
The new customer is saved to customers_database.txt, so it survives a server restart.
SUCCESS is only sent once the save has worked.
The server then asks "Enter Username" again so the new customer can log in.

LOGIN
The server asks "Enter Username", then "Enter Password".
The username must exist and the password must match the one given at REGISTER.
Test customers (Bhagy, Christina, John) have no password: leave the password
blank (just press Enter).
Returns:  Checking Details...
          Log In Successful. What do you want to do?
or:       Checking Details...
          Log In Failed. Please try again.     (then "Enter Username" again)
There is no limit on the number of attempts.

LOGOUT
Typed once logged in. Ends the session without closing the connection.
Returns:  Log Out Successful. Goodbye <Username>.
          Enter Username
The server then goes back to the login prompt, so another customer can log in
(or REGISTER) without restarting the client.

Once logged in, a customer enters the commands below and sees the messages returned

SHOWMYACCOUNTS
Returns all of the customer's accounts and current balances on one line, separated by commas.
e.g. Savings: 1000.0, Cheque: 250.0

NEWACCOUNT <Type>
e.g. NEWACCOUNT Savings
Creates a new account for the logged-in customer.
Opening balance is always 0.
Valid types only: Savings, Cheque, Investment.
Each customer may have at most one account of each type.
Returns SUCCESS, or FAIL: <reason>, one of:
  FAIL: Type NEWACCOUNT <Type>, for example NEWACCOUNT Savings
  FAIL: Account type must be Savings, Cheque or Investment
  FAIL: You already have a <Type> account
  FAIL: Customer data could not be loaded, so changes cannot be saved right now
  FAIL: Your details could not be saved, please try again later
An Opening transaction is recorded so SHOWACTIVITY has something to show.

SHOWACTIVITY <AccountType>
e.g. SHOWACTIVITY Savings
Returns the account's transactions on one line, separated by semicolons:
  <amount> | <date> | <beneficiary>; <amount> | <date> | <beneficiary>
e.g. 100.0 | 2026-11-17 | Bhagy; -20.0 | 2026-11-18 | Shop
If the account has no transactions yet: No transactions
Returns FAIL: <reason> when the command or account is wrong, one of:
  FAIL: Type SHOWACTIVITY <AccountType>, for example SHOWACTIVITY Savings
  FAIL: Account <AccountType> not found

MOVE <Amount> <From> <To>
e.g. MOVE 100 Main Savings 
Returns SUCCESS or FAIL

PAY <Person/Company> <Amount>
e.g. PAY John 100
Returns SUCCESS or FAIL
