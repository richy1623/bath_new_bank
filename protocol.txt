This document details the protocol for interacting with the NewBank server.  

REGISTER
Type REGISTER on its own at the "Enter Username" prompt, before logging in.
The server then asks for each detail on its own line:
  Enter Full Name      e.g. Alice Smith      (can contain spaces)
  Enter Username       e.g. asmith           (no spaces)
  Enter Password       e.g. my secret        (can contain spaces)
Adds a new customer with no accounts (so nothing to show and a 0.00 total),
and gives them a unique number ID (one more than the highest ID so far).
Returns SUCCESS, or FAIL: <reason>, one of:
  FAIL: Full name cannot be empty
  FAIL: Username cannot be empty or contain spaces
  FAIL: Password cannot be empty
  FAIL: Full name, username and password cannot contain file separators (, ; # | ~ :)
  FAIL: Username <username> is already taken
  FAIL: Your details could not be saved, please try again later
  FAIL: Customer data could not be loaded, so new customers cannot be saved right now
Typing the old one-line form (REGISTER followed by details) returns:
  FAIL: Type REGISTER on its own and you will be asked for each detail
The new customer is saved to customers_database.txt, so it survives a server restart.
SUCCESS is only sent once the save has worked.
The server then asks "Enter Username" again so the new customer can log in.

LOGIN
The server asks "Enter Username", then "Enter Password".
The username must exist and the password must match the one given at REGISTER.
Test customers (Bhagy, Christina, John) have no password: leave the password
blank (just press Enter).
Staff log in the same way. The default staff user is Staff, password staff123.
There is no staff sign-up: staff users are seeded in customers_database.txt.
Returns:  Checking Details...
          Log In Successful. What do you want to do?
or, for staff (role STAFF in the file):
          Checking Details...
          Log In Successful. Staff menu: SETSTATUS <AccountNumber> <Status>, MENU, LOGOUT
or:       Checking Details...
          Log In Failed. Please try again.     (then "Enter Username" again)
There is no limit on the number of attempts.

LOGOUT
Typed once logged in. Ends the session without closing the connection.
Returns:  Log Out Successful. Goodbye <Username>.
          Enter Username
The server then goes back to the login prompt, so another customer can log in
(or REGISTER) without restarting the client.

SETSTATUS <AccountNumber> <Status>
e.g. SETSTATUS 00000102 Active
Staff only. Changes the status of any customer's account.
Status is InReview, Active, Inactive or Closed (any capitalisation).
The change is saved to customers_database.txt before SUCCESS is sent.
Returns SUCCESS, or FAIL: <reason>, one of:
  FAIL: Type SETSTATUS <AccountNumber> <Status>, for example SETSTATUS 00000102 Active
  FAIL: Status must be InReview, Active, Inactive or Closed
  FAIL: Account <AccountNumber> not found
  FAIL: An account can only be closed when its balance is 0
  FAIL: A closed account cannot be reopened
  FAIL: Customer data could not be loaded, so changes cannot be saved right now
  FAIL: Your details could not be saved, please try again later
A customer typing SETSTATUS gets: FAIL: Only staff can change account statuses

MENU
Staff only. Shows the staff menu again:
  Staff menu: SETSTATUS <AccountNumber> <Status>, MENU, LOGOUT
A customer typing MENU gets: FAIL: Only staff can use the staff menu
Staff typing anything not on the staff menu, including the customer commands
below, get:
  FAIL: Not a staff command. Type MENU to see the staff menu

Once logged in, a customer enters the commands below and sees the messages returned

SHOWMYACCOUNTS
Returns all of the customer's accounts and current balances on one line, separated by commas.
e.g. Savings: 1000.0, Cheque: 250.0
Closed accounts are left out. Use SHOWACCOUNTDETAILS to see them.

NEWACCOUNT <Type>
e.g. NEWACCOUNT Savings
Creates a new account for the logged-in customer.
Opening balance is always 0.
The account starts as InReview, so it cannot send or receive money until the bank
makes it Active.
Valid types only: Savings, Cheque, Investment.
Each customer may have at most one open account of each type. Closed accounts don't
count, so a type can be opened again with a new account number.
Each customer may have at most 99 accounts in total, including closed ones.
Returns SUCCESS, or FAIL: <reason>, one of:
  FAIL: Type NEWACCOUNT <Type>, for example NEWACCOUNT Savings
  FAIL: Account type must be Savings, Cheque or Investment
  FAIL: You already have a <Type> account
  FAIL: You cannot open any more accounts
  FAIL: Customer data could not be loaded, so changes cannot be saved right now
  FAIL: Your details could not be saved, please try again later
An Opening transaction is recorded so SHOWACTIVITY has something to show.

SHOWACTIVITY <AccountType>
e.g. SHOWACTIVITY Savings
Returns the account's transactions on one line, separated by semicolons:
  <amount> | <date> | <beneficiary>; <amount> | <date> | <beneficiary>
e.g. 100.0 | 2026-11-17 | Bhagy; -20.0 | 2026-11-18 | Shop
If the account has no transactions yet: No transactions
Returns FAIL: <reason> when the command or account is wrong, one of:
  FAIL: Type SHOWACTIVITY <AccountType>, for example SHOWACTIVITY Savings
  FAIL: Account <AccountType> not found
If the customer has both open and closed accounts of that type, this shows the open one.

MOVE <Amount> <From> <To>
e.g. MOVE 100 Main Savings 
Returns FAIL: MOVE is not implemented

PAY <Person/Company> <Amount>
e.g. PAY John 100
Returns SUCCESS or FAIL (not implemented)

SHOWACCOUNTDETAILS
Lists only the logged-in customer's accounts on one line:
  <type> | <account number> | <status> | <balance>; ...
e.g. Savings | 00000101 | Active | 1000.0
Account numbers contain digits and must be copied including leading zeros.
New accounts are InReview. Old account files receive stable numbers and load
as InReview. Account numbers and statuses are saved with the balances.
Account statuses:
  InReview  cannot send or receive money
  Active    can send and receive money
  Inactive  can receive transfers from other customers, but cannot send money
  Closed    cannot send or receive money
An account can only be closed when its balance is 0, and it cannot be reopened afterwards.
Staff change statuses with SETSTATUS.
Unlike SHOWMYACCOUNTS, this command also lists closed accounts.

TRANSFER <FromType> <ReceivingAccountNumber> <Amount>
e.g. TRANSFER Savings 00000301 25.50
Requires login. The source type identifies one of the customer's own accounts.
The receiving account may belong to the logged-in customer or another customer.
The source account must be Active, and the receiving account must be Active or Inactive.
Otherwise the reply is one of:
  FAIL: Your <Type> account is <Status>. Only Active accounts can send money
  FAIL: The receiving account cannot receive money
Amounts must be positive plain decimal values with one or two decimal places, at most
999999999999.99. Scientific notation and explicit plus signs are rejected.
Returns SUCCESS only after both updated balances and both activity records are saved.
The sender's activity records a negative amount and the receiving account number;
the receiver's activity records a positive amount and the sending account number.
Use SHOWACTIVITY <Type> to see the records.
If saving fails, both balances and both histories are restored.
Possible failure reasons include invalid parameters or amount, missing source or
receiving account, selecting the same account as both source and destination, account
status, insufficient funds, and a file-save error. The reply is FAIL: <reason>.
